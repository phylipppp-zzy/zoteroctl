# 用 zoteroctl 管理 Zotero 文献库的操作规范（供 AI 助手使用）

本文件写给 Claude Code、Codex 等代用户操作 Zotero 的 AI 助手。命令的具体用法见 [README](../README.md)；实际能力以 `zoteroctl --help` 为准。

## 1 对象和通用流程

Zotero 里每个父条目、附件、笔记、分类都有独立的 key。题名、作者、来源和摘要属于父条目；PDF 和笔记是父条目的子对象；分类和标签加在父条目上。命令必须使用对应对象的 key。

- 先复用已有条目再补缺失内容。不要为译本、新版本或另一个分类重复新建父条目。
- 只读查询可以直接执行。新增、修改、删除都按这个顺序：读取现状 → 列出具体变更 → 预览（不加 `--apply`） → 按用户授权执行 → 回读检查。
- 用户只要方案时，不改动文献库。
- 批量修改前先运行 `snapshot`。每批最多 10 条，串行执行，一批完成并核对后再做下一批。
- 遇到 412 版本冲突时，重新读取后再计算变更。执行失败时，先查清哪些已经成功，不要整批盲目重试。

## 2 查询

- `list` 只列顶层条目。要完整列出某个父条目的附件和笔记，用 `list --all --full`，筛选 `data.parentItem == KEY` 的对象。
- 按分类筛选看 `data.collections`，按标签筛选看 `data.tags`。统计时区分父条目、附件、笔记和批注，并检查 `data.deleted`。
- 查重不能只靠一次关键词搜索。要比较规范化后的 DOI、arXiv 编号、来源 URL、题名、作者和版本关系。
- 区分三种状态：条目元数据存在、PDF 可以下载、全文已经读过。读全文前先 `fetch` 并实际打开文件，不能把摘要或附件标题当作读过全文。
- 报告查询结果时，写出 key、题名、类型、分类、标签和附件/笔记情况。

## 3 新增

- 先核验来源，再查重。元数据（作者、摘要、编号）要从 arXiv、Crossref、出版社页面等权威来源获取，不要编造；查不到的字段留空，并在报告里说明。
- 新条目沿用文献库现有的分类体系和标签体系。动手前先运行 `collections`，并统计现有标签的写法。
- 上传 PDF 前，确认文件内容与父条目对应，例如核对首页题名。上传后检查 `verified` 字段，失败时报告附件 key。
- `note` 每次都新建一条笔记。要更新已有笔记，用 `update NOTEKEY --fields`。
- 文件存储方式要和用户的 Zotero 设置一致。用户用 WebDAV 时，先确认 `status` 显示 `file_storage: webdav`，否则上传的文件在桌面端打不开。

## 4 修改

- 只改明确指定的字段，保留原 key。
- `--tag` 和 `--collection` 只做添加。把条目加入新分类，不等于把它从旧分类移出；加上 `status:read`，也不会自动去掉 `status:to-read`。要替换就同时写 `--tag` 和 `--remove-tag`。
- 目前没有把条目移出分类、重命名分类的命令。需要时先给出变更清单，等用户确认后另写脚本执行。
- 改完后回读，报告各项的实际新值和尚未完成的事项。

## 5 删除

- 先分清要删的是什么：父条目、一个附件、一条笔记、一个分类，还是只是某个分类关系。这几种不能互相替代。
- 删除前列出目标的 key、题名、类型、子对象和删除影响，必要的元数据、笔记、文件和批注要先保全。用户明确授权目标和范围后才执行。
- 用户说“删除某个分类里的东西”时，要逐条看清楚内容再动手。插件的数据条目（例如名为“Addon Item”、底下挂着几十条 JSON 笔记的条目）和同时属于其他分类的正经文献，都应该先向用户说明情况再决定。
- `delete` 是永久删除，不经过回收站。删除附件记录后，存储中的文件不会被清理。
- 分类没有回收站，同名分类重建后也恢复不了原来的 key 和成员关系。`--include-subcollections` 只在用户授权删除整棵分类树时使用。
- 删除后重新查询，确认实际状态。目标已经不存在时，如实报告，不要重复执行。

## 6 凭据和交互

- 不要让用户把 API key 或密码贴进对话。让用户自己在终端运行 `configure` / `configure-webdav`，这两个命令会提示输入，输入内容不显示。
- WebDAV 返回 401、而 Zotero 桌面端验证能通过时，先看报错里给出的密码长度。常见原因是从 Zotero 密码框复制没有成功，剪贴板里还是用户名；不要先怀疑网络或服务器。

## 7 可以直接放进 CLAUDE.md / AGENTS.md 的约定

> 使用 zoteroctl 管理 Zotero 文献库。先读取文献库和对象的现状，再按用户指定的范围新增、查询、修改或删除。优先复用已有父条目，使用真实 key。修改前给出具体预览，按用户已有的授权执行，执行后回读核对。删除前要说清对象及影响，并先保全附件、笔记和批注。添加标签或分类不等于替换。不要反复新建同一条笔记。遇到版本冲突时重新读取；执行失败后先检查实际结果。区分元数据存在、PDF 可读和全文已读三种状态。用户只要方案时，不执行任何写入。
